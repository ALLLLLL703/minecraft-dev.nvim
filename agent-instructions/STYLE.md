# 编码风格

## 核心原则

- 通过命名、数据流和模块边界表达意图，优先直接清晰的实现，不使用聪明但难追踪的压缩写法。
- 模块只承担一个清晰职责；共享机制放入最窄的公共模块，平台规则留在对应生成器中。
- 抽象必须有当前调用者，并实际减少重复、隔离变化或强化不变量。

## Lua 模块

- 默认在文件顶部集中 `require` 依赖。只有可选依赖、避免循环依赖或确有延迟加载需求时才局部加载，并让原因可见。
- 公共入口返回稳定、可判断的结果或结构化错误；不得以通知文本代替程序化错误契约。
- 同步和异步接口必须明确区分。回调只能完成一次，取消、超时和失败均为显式终态。
- 网络、Git、Gradle、解压和大量文件 IO 不得阻塞 Neovim 主循环；回调进入 Neovim API 前使用正确的调度边界。
- 可复用公共 API 使用 LuaLS/EmmyLua 注解说明参数、返回值、错误和异步约定。

## 模板与生成器

- 完整生成模板存放在独立模板或资源文件中，不使用大型硬编码格式字符串。
- 小型条件化元数据可由专用 builder 生成；不要为了形式统一而把每个短片段机械外置。
- 平台、构建系统和语言能力必须来自共享注册信息，命令补全、校验、向导和非交互 API 不得维护平行列表。
- 模板目标路径、归档条目和输出目录必须限制在允许根目录内。模板求值器不得执行任意 Lua 或 shell。
- 生成失败不得伪装成功，也不得留下看似完整的半成品项目。

## 配置、文本与依赖

- 用户可见文本通过项目的消息或本地化层访问，不在业务逻辑中散落重复文案。
- 用户配置先复制、合并和验证，再进入运行时；不得保存后直接修改调用者传入的表。
- 优先使用 Neovim 内置 API。可选插件通过安全加载接入，并保留无需该插件的核心路径。
- 注释只解释原因、不变量、兼容约束或非显然控制流，不复述代码。
