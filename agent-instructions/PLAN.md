# 实现计划规则

- 只有用户要求计划或任务确实需要先形成计划时，才编写实现计划。
- 写计划前先读取相关代码、测试、公共接口、适用说明文件及必要历史，不得臆造不存在的文件或符号。
- 开头说明目标、当前行为、期望行为、范围、非目标、约束、假设和可观察完成条件。
- 标明受影响的模块、公共接口、调用方、数据/控制流、兼容边界和文档。
- 步骤按依赖顺序组织；每一步说明目的、具体修改位置、行为、不变量、错误路径和完成该步所需验证。
- API、配置、模板格式、依赖或生成物变化必须同时说明生产者、消费者、兼容策略和迁移影响。
- 给出项目当前可执行的验证策略，包括 Neovim MCP 场景、生成项目验证以及需要的 Gradle/Maven 检查。
- 记录风险、被否决的重要方案和仍需用户决定的问题；遇到决策分支时通过 `question` 工具确认。
- 计划描述工程决策和结果，不罗列打开文件、输入文本或保存文件等编辑动作。
- 调查推翻假设后及时修订计划，使其始终代表实际实现方向。
